## Context

Judges score Design on completeness. Every screen uses Forge UI Kit (`render: native`) so it matches Jira in light
and dark themes, and one component, the conflict card, looks the same wherever it appears. Technical
specification §15. Built against a mock `CoreService` first (spec 0002).

## Design

### Conflict card

| Element    | Content                                                                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Header     | "DEC-3: No customer email addresses in application logs"                                                                                         |
| Meta line  | Owner, date decided, kind, and "checked by rule" or "checked by model, 86% confidence"                                                           |
| Two quotes | "The decision says" / "This work item says", side by side, each linked to its source                                                             |
| Evidence   | For rule conflicts, the exact matched passage, highlighted                                                                                       |
| Actions    | **Follow** (opens the editor; stays open until rechecked), **Supersede** (form: new statement + reason, same scope), **Dismiss** (note required) |
| Footer     | Who can resolve, if the current user cannot                                                                                                      |

### Issue panel `precedent-panel`

| State                 | What the user sees                                                                                                             |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| No decisions in scope | "No decisions apply to this work item yet." + Record decision                                                                  |
| Clear                 | "3 decisions apply. No conflicts." + collapsed list                                                                            |
| Conflicts             | One card per open conflict, most confident first, then other decisions in scope                                                |
| Following             | "Waiting for your edit to be rechecked" on the card                                                                            |
| Proposals waiting     | "1 decision to confirm": statement, source quote, proposed kind and rule, Confirm / Edit / Reject (Confirm only for approvers) |
| Checking              | Spinner, "Checking against 3 decisions"                                                                                        |
| Inconclusive          | "Could not check DEC-7: model unavailable." + Check again; coverage gaps: "2 of 11 decisions not checked yet"                  |
| Restricted            | "1 restricted decision applies. Ask its owner."                                                                                |
| Error                 | A plain message and Retry. Never an empty panel.                                                                               |

Record decision form: statement (required), rationale, kind (select with a model suggestion), scope (defaults to
project + components), review-by date.

### Badge `precedent-badge`

"Clear", "2 conflicts", "1 to confirm", "Checking", "Not fully checked". Selecting it scrolls to the panel.

### Ledger `precedent-ledger`

Filters: status, kind, scope, owner, search. Table: id, statement, kind, scope, owner, status, decided, open
conflicts. Decision view: statement, rationale, rule in readable form, evidence quotes, history (supersede chain
with reasons), every check and its resolution, repositories it is published to. Actions: supersede, expire, change
scope, publish to a repository, copy agent rules. "Needs an owner" list for overlapping disagreeing decisions.
Empty: "No decisions yet. Record one from any work item, or load the sample workspace."

### Setup page `precedent-setup`

Health checks (Rovo available, Confluence connected, validator in use, MCP external access) · Load / Reset sample
workspace · Scope mapping (projects/components → repo slugs) · Approvers per scope · Guard settings (threshold,
lenient/strict, fail-open/closed, open resolution) · Usage (tokens today, cap) · Three guides (add the validator,
create a Rovo Studio agent, connect an external MCP client).

### Rules

Plain language; no internal terms on screen; colour is never the only signal; every state above is built.

## Interfaces

Resolver functions in `src/resolver.ts`, one per core function the screens need, each passing `toCtx(context,
"panel")`.

## Acceptance criteria

1. Every state in the panel table renders from a mock core (snapshot or render test per state).
2. Confirm is shown only to approvers; non-approvers see who can confirm.
3. Follow keeps the card in a "following" state until the recheck clears it.
4. No screen shows internal field names.

Confluence byline (S2). Lineage diagram (cut).
